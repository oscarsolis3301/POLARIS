# POLARIS 6.2.0 — Parallel work that can't eat itself

## Context

Three failures surfaced from real parallel runs on POLARIS-managed repos, plus one standing manual chore:

1. **A session deleted another session's in-use worktree.** `.polaris/wt/ARC-428` was removed
   mid-command by a sibling session right after the task's PR merged (remote branch auto-deleted).
   Everything uncommitted in that worktree was lost — ~15 min of reconstruction, and it was pure luck
   the agent had scripted most of its edits. 6.1.0 ("enforced isolation") gated the *shared primary*;
   nothing yet proves a *worktree* is live before removal.
2. **Auto mode still prompts.** "Do you want to proceed with EnterWorktree/Workflow" appears even in
   auto mode. The owner's standing rule: in auto mode POLARIS sessions must never prompt unless the
   action is genuinely destructive/irreversible. The kit's machine-arming (permission rules +
   readonly-allow hook) doesn't cover the newer harness tools.
3. **The machine sleeps mid-run.** Long multi-session runs die when the device locks/sleeps. Wanted:
   ONE machine-singleton keep-awake daemon that presses F15 (harmless key, defeats idle detection)
   on an interval — started by whichever session comes first, kept alive while ANY POLARIS session
   on the machine is still working, stopped only when ALL sessions are done. Never one per session.
4. **Screenshot self-validation is a manual paste.** Every visual task needs the "SEEING YOUR WORK"
   prompt pasted by hand (shot.py, unique filenames, capture lock, LOOK at the PNG with Read).
   A green suite shipped a visually broken page once — this check must be part of the BUILDER/SOLO
   contract, driven by CONVENTIONS keys so each repo can plug in its own capture tool.

Deliverable: kit changes in `kit/`, dogfooded into `ops/`, released as 6.2.0 per the
release-everywhere ritual (VERSION + CHANGELOG + tag + published release in one motion).

**Owner decisions recorded at the plan gate (2026-09-01):**
- **T-095 (permission rules, risk: high) merge is PRE-APPROVED** — the exact rule set is the six
  bare tool names below, never `ExitPlanMode`/`AskUserQuestion`. No mid-sprint gate.
- **Scope includes the product repo:** after the 6.2.0 release, run `polaris update` in the repo

## Workstreams

### WS1 — Worktree liveness: no session may remove a worktree it cannot prove dead

**Root cause (found, exact):** 6.1.0 protected the shared primary, never a session's worktree.
- `cmd_done` (`kit/ops/lib/integrate.sh:100-101`) runs `git worktree remove --force` — `--force` is
  precisely the flag that disables git's built-in refusal to delete a dirty worktree — with no
  dirty check, no liveness check, result discarded (`2>/dev/null || true`). `cmd_release`
  (`builder.sh:330-331`) has the identical two lines, gated only on column membership.
- The fan-out that makes it routine: `landing: self` (default) → the LAST builder's
  `self_land` → seal loop (`builder.sh:299-306`) runs `done <tid>` on EVERY landed task in
  `review/` — i.e. sessions routinely run `done` on tasks they don't own. That is exactly how
  ARC-428 died: sibling's task merged via PR → last-out session's seal fan-out force-removed the
  sibling's still-in-use worktree.
- No liveness is even possible today: the task lock (`core.sh:365-369`) is the ONLY lock in the
  system with no PID — `who()` is user@host, identical for all N sessions.
- `checkout-guard.sh` doesn't list `worktree remove|prune` (only `worktree add`) and is
  unconditionally silent inside ANY worktree — a session in wt B can destroy wt A ungated.
- Aftershock: `done` also deletes `feat/<ID>` local+remote; a later `resume`/`wt_add` silently
  recreates the branch FROM `$BASE` — silent history reset.
- `sweep --fix` has NO worktree pass, yet two places prescribe it as the stray-worktree remedy.

Patch (settled design — verified against the tree, incl. the two call sites re-read first-hand):

- **Liveness beat at `$GCD/worktrees/<ID>/polaris-beat`** — git's own per-worktree admin dir:
  survives `lock_drop` (a lingering session stays protected after `done`), dies automatically with
  worktree removal, never pollutes the repo tree. **Deliberately NO pid in the task-lock meta** —
  `$$` is per-CLI-invocation (dead seconds after claim writes it) and `who()` is user@host, same
  for all N sessions; a pid line would institutionalize a lie, and the 3-line meta parsers stay
  untouched. Writers: `beat_touch` (epoch content) from claim/resume/verify/handoff + an inline
  `ops/polaris` dispatch-preamble when cwd is in a worktree; zero-fork `: >` mtime touches in
  `checkout-guard.sh` + `ownership-guard.sh` (NOT `readonly-allow.sh` — its only-ever-ALLOWS
  contract must not gain writes). Reader `beat_age`: content-first, mtime fallback, unreadable ⇒
  idle (lets drills fake idleness with `echo 1 >`). Live = age < `wt_live_minutes` (new key,
  default 15 in kit code: every Edit/Bash/polaris call refreshes; `bg wait` chunks beat ≤5 min
  apart; ladder 15m < int-stale 45m < stale_hours 4h). False-idle never destroys work (dirty →
  archive); false-live merely defers cleanup.
- **One removal primitive `wt_remove <ID>` (workspace.sh)** — rc 0 removed / 1 left / 2 archived;
  **`--force` disappears from lib code entirely**. Archive = `mv` to
  `.polaris/wt-archive/<ID>-<epoch>` (tracked mods AND untracked scratch preserved —
  archive-don't-delete) + strip the dangling `.git` file + `git worktree prune`. Every failure
  (Windows EBUSY) degrades to LEAVE + note — never a die mid-delete, never a partial delete.
- **Decision table (caller × dirty × live):** `done` — clean+idle ⇒ remove; clean+live ⇒ LEAVE +
  note, skip local `branch -D` (checked out there); dirty+live ⇒ LEAVE louder; dirty+idle ⇒
  archive then branch -D. `release` — own-lane dirty ⇒ archive (EBUSY ⇒ leave + "cd out");
  clean ⇒ remove (committed work lives on `feat/<ID>`, which release keeps); **dirty+live from
  OUTSIDE ⇒ die** naming beat age + the explicit `rm <beat>` takeover. `resume` — **live beat ⇒
  die** unless cwd already inside that worktree. `sweep --fix` — the deferred reaper: idle+clean ⇒
  remove (+ branch -D when task in done/); idle+dirty ⇒ archive; live ⇒ report only. `uninstall` —
  new die when `wt-archive/` is non-empty (the rm -rf must never eat archived work).
- **Own-worktree `done` designed out, not sequenced around:** the handoff just touched its own
  beat ⇒ the seal fan-out's `done <own-ID>` hits clean+live ⇒ LEFT; a session's cwd never vanishes
  mid-command; next `sweep --fix` reaps it once idle. No new flags ⇒ `usage()`/cli-help golden
  untouched; overrides ride die-message remedies.
- **checkout-guard:** inside-worktree fall-through now only for commands containing `worktree`;
  parser gains `remove|prune|move` verbs; those deny EVERYWHERE (primary, own worktree, foreign
  worktree — wt B destroying wt A was exactly the hole) with a second pinned message; common path
  stays byte-identical and fork-free.
- **CONDUCTOR dead-lane rule:** dead = silent past `stale_hours` AND beat idle past
  `wt_live_minutes` — a lane in a long `bg wait` beats every ≤5 min and is NOT dead. `sweep`'s
  STALE line gains "last activity <n>m ago". `resume`'s refusal prints the beat file; running that
  rm IS the explicit takeover.
- **ARC-428 replay under the fix:** the seal fan-out's `done ARC-428` still moves the board
  review→done (it IS landed), but `wt_remove` sees dirty+live ⇒ worktree LEFT, branch kept, note
  printed — the sibling's uncommitted diff intact; later commits go on the still-existing
  `feat/ARC-428`, no silent fresh-cut from `$BASE`.
- **Verification:** new drill `wtreap` (archive-holds-bytes, cross-session refusal, done-leaves-live,
  sweep reaps once backdated, resume refusal); `drill_selfland` gains an own-worktree-survives
  assert; goldens: checkout-guard-denies gains the worktree-remove cases (pinned counts unchanged),
  api-kit pinned to exactly 6 new rows (beat_touch/beat_age/beat_live, wt_remove, drill_wtreap,
  wt_live_minutes); plus a grep-audit of every existing drill's `release` site (all currently
  clean-tree, so the 31 stay green).
### WS2 — Auto mode prompts for nothing it doesn't have to

**Root cause (found):** every POLARIS permission mechanism is Bash-shaped. The kit's allow rules
(`kit/.claude/settings.json`) are exclusively `Bash(...)`/`PowerShell(...)` prefixes; the three
PreToolUse hooks match `Bash` or the edit tools only, and `readonly-allow.sh` hard-exits when
`tool_name != "Bash"`. So `EnterWorktree`, `ExitWorktree`, `Workflow`, `Task`/`Agent` etc. reach the
auto-mode classifier raw, and it prompts. Also: `bootstrap.py`/`admin.sh` write
`defaultMode: "auto"` set-if-absent — an armed machine can never be escalated by update, so the fix
must work *within* auto mode via allow rules, not by flipping the mode.

Patch (settled design — all three merge paths verified to union arbitrary strings, so bare
tool-name rules survive every propagation hop):
- Append exactly six bare tool-name rules to `kit/.claude/settings.json` `permissions.allow` AND
  `kit/ops/bootstrap.py` `PERMS`: `"EnterWorktree"`, `"ExitWorktree"`, `"Workflow"`, `"Task"`,
  `"Agent"`, `"TodoWrite"` (bare name = allow every use; unknown names are inert on older builds).
  **Deliberately absent:** `ExitPlanMode` + `AskUserQuestion` (genuine human gates — allowing them
  would auto-approve the plan gate itself) and `NotebookEdit` (same classifier class as Edit/Write,
  which don't prompt; ownership-guard denies out-of-ownership writes regardless — hook denies beat
  settings allows). Comment block in bootstrap.py records the reasoning.
- **Settings-only — do NOT widen `readonly-allow.sh`:** these allows have no argument conditions,
  and an allow-hook that times out emits nothing — the prompt comes back, which is the bug being
  fixed resurfacing under load. A static rule cannot fail.
- During dogfood, capture the live prompt's exact tool name — if "EnterWorkflow" is a distinct
  spelling on some build, add that exact string too (inert if wrong, fixes nothing if missing).
- Live re-verify `EnterWorktree({path: ".polaris/wt/<ID>"})` (sprint-11's open box): works → note
  in shared-checkout.md v2.5 that the no-prompt claim is now backed; refuses (only accepts
  `.claude/worktrees/`) → pin the absolute-paths/`cd` form as the sole instruction in BUILDER.md,
  SOLO.md, the claim-close print, and the fleet kickoff string; keep the rules (inert).
- New golden `ops/tests/perm-tools.cmd`/`.expected`: the six names present in both files,
  `ExitPlanMode`/`AskUserQuestion` in neither, the two union blocks still intact.

### WS3 — `polaris awake`: one keep-awake daemon per machine, F15, lives until the whole fleet is idle

**Found infrastructure to reuse:** the Windows-safe detach idiom in `bg.sh` (`( … ) & ; pid file`,
no nohup — proven under MSYS); three mkdir-atomic singleton locks (task lock / board mutex /
integration lease — lease is the closest shape: pid + epoch + staleness steal); `.polaris/` runtime
dir convention; `cmd_sweep` as the reaper precedent. **What doesn't exist:** any machine-level
session registry or heartbeat — "all sessions finished" is currently only approximated per-repo.

Patch (settled design — new `kit/ops/lib/awake.sh`, ≤300 lines, `awake_` fns + `cmd_awake`):
- **Machine registry** `~/.claude/polaris/awake/`: `lock/` (mkdir-atomic singleton, int-lease
  recipe), `pid` (written after spawn, bg.sh idiom), `daemon-beat` (rewritten every tick —
  freshness of THIS file, never `kill -0` alone, is the liveness verdict), `repos/<cksum>-<name>`
  (line 1 = repo path, line 2 = its idle-minutes captured at upsert — daemon never parses
  CONVENTIONS), `log` (rotated), `stop` flag (honored < 60 min; `awake start` clears).
- **Heartbeat — three zero-fork sources** (`: > .polaris/awake-beat 2>/dev/null || true`, a
  builtin redirect that cannot fork, block, or fail loudly): (1) the `ops/polaris` entry script
  after env-resolve — every CLI call AND every Edit/Write beats free via `_guard`; (2)
  `readonly-allow.sh` (after its `--test` early-exit, keeping the golden battery byte-identical) —
  every Bash tool call; (3) `checkout-guard.sh` same. Uncovered stretches: pure Read/Grep
  exploration (~5-15 min) — `awake_idle_minutes: 30` default gives 2× margin.
- **Ensure on cold commands only:** a pre-dispatch case in `ops/polaris`
  (`claim|status|doctor|qa|bg|finish|dash|fleet|init-board` → `awake_ensure`) — never on `_guard`
  hot paths. Healthy-daemon cost: one file read + builtin pid check.
- **Daemon = detached bash loop** (the MSYS-proven `( … ) </dev/null >>log 2>&1 &` idiom) spawning
  ONE stateless PowerShell per ~55s tick — no long-lived PS child (a crashed tick costs one press;
  a leaked `SetThreadExecutionState(ES_CONTINUOUS)` would outlive a dead daemon). Windows tick:
  `powershell -NoProfile -NonInteractive -WindowStyle Hidden`: P/Invoke `GetLastInputInfo`; **only
  if input-idle > 60s** → SendKeys `{F15}` — an actively-typing user keeps the machine awake
  themselves and must never catch a stray F15 in a focused app ("without interrupting workflows").
  macOS: `caffeinate -i -t 75` per tick; Linux: `systemd-inhibit`/`xdotool key F15`/log-and-exit.
- **Shutdown — the idle scan is the only authority.** Per tick, a repo is active if: beat age <
  its idle minutes · OR any bg job with no `rc` file and a live pid (rc-file-first) · OR any lock
  dir (incl. `.int-lease`) with epoch younger than 2× idle minutes (the 2× bound stops an orphaned
  lock pinning the machine awake for hours). All repos idle → release pid+lock, exit. `finish`
  NEVER stops the daemon. Crash → trap releases; hard kill → steal path (daemon-beat > 10 min
  stale AND pid dead → respawn). `uninstall` deregisters its repo.
- **Knobs (defaults in kit code — reaches every repo on update, which is what the owner wants):**
  `awake: on` / `awake_idle_minutes: 30`; two KEYS.tsv rows. `awake: off` makes beat/ensure no-ops
  for that repo; a typed `awake start` beats the knob. Doctor line: "`awake: on` but daemon not
  running → `bash ops/polaris awake start`".
- **CLI:** `awake status|start|stop` (usage + dispatch + loader list gain `awake`;
  cli-help/api-kit goldens move — pinned by the one golden-owner task).
- **Drill `awake`** — hermetic + key-press-free via env seams (`POLARIS_AWAKE_HOME`,
  `POLARIS_AWAKE_PRESSER="touch $T/pressed"`, `POLARIS_AWAKE_TICK=1`, idle-seconds override):
  asserts spawn/lock/registry, press fired, re-entrant start no-op, dead-daemon steal, all-idle
  self-shutdown, stop-flag semantics, `awake: off` no-op.
- New contract `ops/contracts/awake.md` + module-layout.md v5 census row.
### WS4 — SEEING YOUR WORK ships in the kit: visual self-check in BUILDER/SOLO via CONVENTIONS keys

### WS5 — Gap audit: the remaining ways parallel sessions clobber each other (triage: fix now vs backlog)

Found beyond the headline race (all verified with file:line):
1. Orphan-lock window in `claim` — lock taken BEFORE the mutex; concurrent `sweep --fix` drops a mid-claim lock.
2. `resume` adopts any lock unconditionally — two sessions end up sharing one worktree.
3. Board-mutex steal is pid-blind at 120s while the mutex is held across up-to-5 network round trips — slow remote → live mutex stolen, board mutations interleave.
4. Concurrent `sync_board` fetches share the primary's `FETCH_HEAD`.
5. `done` commits to the shared primary index with only a brief index.lock retry.
6. `unpark` pops the NEWEST park stash — session A's unpark can restore session B's parked tree.
7. `wave_on` switches the shared primary's branch mid-land (sessions reading the primary see wave content).
8. `suite-stamp` keyed on HEAD sha only — a wave-branch green can satisfy another session's qa/finish.
9. `bg` registry is one flat namespace — `bg run test` collides; `--force` kills the other session's live job.
10. Branch delete + silent branch recreation from `$BASE` (partially WS1).
11. `sweep --fix` deletes remote branches on ancestry proof only.
12. `finish` treats stray worktrees as caveat-only (partly moot under WS1).

**Triage (settled):** fix now = #1 (sweep orphan grace: never drop a lock younger than 120s or with
a live pid), #2 (resume refuses to adopt a lock with live pid + fresh beat), #3 (mutex steal
requires dead/absent pid; sync_board re-stamps the mutex epoch each retry so a slow remote looks
alive), #4 (rider on #3: derive remote tip via `ls-remote`, never shared FETCH_HEAD), #6 (park
stash names carry `<epoch>-<pid>`; unpark pops only OUR newest park, refuses another live session's,
`--any` keeps crash recovery), #8 (stamp the suite green only if HEAD unmoved + tree still clean
AFTER the run), #9 (bg jobs record owner pid; `--force` on a foreign live job refuses), #10
remainder (`wt_add` warns loudly when recreating a previously-existing branch from `$BASE`), #11
(`sweep --fix` never deletes today's `integrate/<date>`).
**Backlog (IDEAS.md lines):** #5 (primary-index retry hardening), #7 (dedicated integrate worktree
so the primary never leaves base — architecture change).
**Leave:** #12 (caveat semantics correct by design; text stays true once sweep is liveness-safe).
