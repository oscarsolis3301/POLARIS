## SPRINT A — the shape

`ops/SURFACES.tsv`, TAB-separated, modeled on RULES.tsv:

    surface<TAB>tests<TAB>cmd<TAB>note

- one glob per column; a surface needing several globs gets several rows
- `cmd` is a COMPLETE shell command run in $PRIMARY, or `-` = derive from the `test_select:` template
- **selection scopes `test:` ONLY.** typecheck must be whole-project (a partial typecheck is a lie),
  build must be whole-project or `generated:` breaks, lint is already fast, uat needs its own map.
- **`test_select:` absent => selection OFF => byte-identical to today.** This is what lets `update`
  ship it everywhere and change nothing.

### Decisions the contract MUST pin

- **D1 — who writes rows.** NOT the Builder, and NEVER by editing the file. A row buys R1's savings and
  arms R2 against you, so the rational Builder move is to write none. Rows are a `surface:` frontmatter
  list set by the PLANNER at the plan gate, applied by `cmd_done` beside `map_delta` (integrate.sh:81).
  Nobody owns the file; only `done` writes it. This also kills the Invariant-2 hotspot.
- **D2 — the file is RULES-guarded `path`.** Closes the delete-the-row escape with machinery that
  already exists. CONSEQUENCE: no task may both arm that rule and write rows, because check_rules sees
  the final diff. **This sprint ships SURFACES.tsv EMPTY**; this repo's own rows arrive next sprint via
  `surface:`, which is the intended channel anyway.
- **D3 — no gate on a brand-new surface with no row.** In a 500-file repo with zero rows that blocks
  every task, and the cheapest satisfying move is a lie ("src/x.py -> tests/") which then makes R1 SKIP
  real tests. Never build a gate whose cheapest satisfying move is a lie.
- **D4 — never call the freshness gate from `cmd_guard`.** The write-time guard sees one path at a time
  and cannot know the test edit is coming; it would deny the first edit of every task and burn the 10s
  hook budget. Call it from cmd_verify / cmd_handoff / cmd_audit / cmd_land only.
- **D5 — the suite stamp must not be allowed to lie. OPEN — the Planner decides and pins it.**
  `.polaris/suite-stamp` says "this commit is green" and `finish` skips on it. A scoped run that writes
  that stamp unchanged blesses code nobody fully tested. But note the arithmetic: express-land-full +
  finish-skip = 805s today; express-land-scoped + finish-full = 855s, which is WORSE. So scoping only
  pays if a scoped green is accepted as sufficient to LAND. Recommended: add a third field recording the
  proven scope (both readers use `cut -d' ' -f1`, so it is backward-compatible by construction); `finish`
  accepts a scoped stamp because it is the per-change gate; **the RELEASE path demands `full`**, and CI
  already runs the full serial suite on three OSes. If the Planner disagrees, it must say what does.
- **D6 — R1's failure mode is UNSAFE, not safe.** Fail-safe covers *unmapped*, never *mis-mapped*: a
  wrong `tests` glob silently skips coverage while reporting green. Mitigation is `polaris surfaces`
  health: refuse a self-covering row (surface glob matching its own tests glob), flag a glob matching
  zero tracked files or more than ~200, wire into `drift`.

## B0 (NEW, and it gates the value of all of Sprint A) — propagation AND activation

Two separate problems. Only the first is solved today.

**Propagation — already works, needs a release.** `update --auto` runs at SessionStart, applies minor
and patch automatically on a quiet board, and 6.3.1 -> 6.4.0 is a minor bump. `update --all` walks the
per-machine registry (`~/.claude/polaris/awake/repos/<cksum-of-abs-path>`; 3 repos on this box). Other
COMPUTERS reach it through `channel:` in ops/VERSION, so a published release propagates on its own.
Nothing new is needed here EXCEPT actually cutting the release, in all four places at once (kit/ops/VERSION,
CHANGELOG, git tag, published GitHub release carrying polaris-v5.zip) — memory of sprint 13: a sharded
green is NOT a CI green, and 6.2.0 / 6.2.1 / 6.3.0 are all tags that were cut and never shipped.

**Activation — NOT solved, and this is the real work.** `update` never writes a repo's CONVENTIONS.md
(deliberate: v6.0 principle). So an updated repo gets the machinery with `test_select:` unset and
`ops/SURFACES.tsv` empty => selection OFF => byte-identical to today => NO speed-up. Every existing
install would be upgraded and none would be faster. POLARIS must therefore map a repo's surfaces
ITSELF.

### The constraint that must govern B0, or this ships a foot-gun
Contract D6 already records it: R1's failure mode is UNSAFE, not safe. Unmapped is fail-safe (runs
everything); MIS-mapped silently skips real coverage while reporting green. Auto-generating rows turns
a hand-written risk into an automatic one, in repos the owner is not watching.

Therefore auto-activation must be CONSERVATIVE by construction:
- generate a row ONLY where the source/test correspondence is unambiguous (an obvious directory or
  basename pairing the stack's own convention already implies); anything ambiguous => NO row => full suite
- rows must OVER-select rather than under-select when in doubt
- `test_select:` may only be derived where the repo's test runner provably accepts path arguments
- the release/publish path and CI keep running the FULL suite, always — that is the backstop that makes
  scoping acceptable at all
- prefer proposing to stdout (`surfaces --scaffold`, the `check --scaffold` discipline) over silent
  writes; if it writes, it writes only the unambiguous subset and says exactly what it did

A gate whose cheapest satisfying move is a lie is forbidden (D3). The same logic binds a GENERATOR:
a scaffold that guesses to look useful is worse than one that emits three rows and admits the rest.
