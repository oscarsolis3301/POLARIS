# POLARIS 6.2.0 — Parallel work that can't eat itself (v2 — supersedes `plans/v1.md`)

## Context

Five parallel Claude Code chats work one repo through POLARIS, and four things still break:
1. **Sessions delete each other's work.** A sibling's seal fan-out ran `done ARC-428`, which
   `git worktree remove --force`d a worktree another session was still typing in. Everything
   uncommitted died. 6.1.0 guarded the shared primary; nothing proves a *worktree* is dead before
   removal, and three more destroyers (`git clean`, `rm -rf .polaris`, by-name process kills — the
   "port 8001 instance vanished" incident) have no guard at all.
2. **Auto mode still prompts** ("Do you want to proceed with EnterWorktree"). Every kit permission
   rule is `Bash(...)`/`PowerShell(...)`; nothing pre-authorizes the harness's own tools, so five
   top-level sessions each stall on the same click. The owner's rule: in auto mode a POLARIS session
   asks nothing unless the harness itself insists.
3. **The machine sleeps mid-run.** Wanted: ONE machine-wide keep-awake owner that presses
   F13/F14/F15 while ANY session is still working and stops only when ALL are done — never one
   per session, never interrupting a human who is typing.
4. **"SEEING YOUR WORK" is pasted by hand** every visual task. It becomes part of the Builder/SOLO
   contract, driven by CONVENTIONS keys so each repo plugs in its own capture tool (`tools/shot.py`).

`plans/v1.md` (2026-09-01) already designed WS1–WS5 well. This v2 keeps every settled decision that
survived a line-by-line re-audit of the tree at `e078d68`, corrects what did not, and adds the gaps
the audit found. Deliverable is unchanged: kit changes in `kit/`, dogfooded into `ops/`, released as
6.2.0 in one motion (VERSION + CHANGELOG + tag + published zip), then `polaris update` + keys in the
product repo (path supplied by the owner at execution).

**Owner decisions carried from v1 (2026-09-01):** the permission-rules task (`risk: high`) merge is
PRE-APPROVED for exactly the bare tool names listed in WS2; the product-repo step is in scope.

## Gap catalogue — what v1 missed (new in v2)

**G1. `git clean -fdx` in the primary deletes `.polaris/` wholesale** (gitignored, so `-x` targets it):
every worktree, the index, the brain, bg logs. No hook covers `clean`. → deny everywhere except `-n`.
**G2. Non-git destroyers have no guard**: `rm -rf .polaris*`, `Remove-Item -Recurse .polaris`,
and by-name process kills (`taskkill /IM`, `Stop-Process -Name`, `Get-Process … | Stop-Process`,
`pkill`, `killall`, `kill -9 -1`, `npx kill-port`, `fuser -k`). The 8001 kill was a launcher
reclaiming a port by killing whatever held it. → checkout-guard gains a non-git branch: broad kills
denied, pid-targeted kills allowed (you may only kill what you started — `bg` knows your jobs).
**G3. Port collisions.** Five sessions screenshotting five worktrees each need their own server.
→ `port_base:` key; `pack` prints a per-task port (`port_base + numeric-id mod 100`) and
substitutes `{PORT}`/`{ID}` into `serve:`/`shot:` templates. The human's port is never touched.
**G4. `resume` adopts any lock unconditionally** (`builder.sh:592`) — the lock-side twin of the
worktree bug and the *documented* takeover path. → beat-gated (WS1).
**G5. Auto-`park` stashes a sibling's uncommitted primary edits** (six auto call sites:
`integrate.sh:246,343,424,562,667`, `admin.sh:368`; `--include-untracked`). Combined with
unpark-newest, the wrong session restores the wrong dirt. → park names carry `<epoch>-<pid>`, park
prints the stashed paths loudly, `unpark` pops only OUR park (`--any` for crash recovery), `status`
lists parks with age. (Dedicated integrate worktree = backlog, architecture change.)
**G6. Same-name bg jobs collide across sessions** (`bg run qa` ×2): `bg_rotate` `rm -rf`s the
`.prev` archive, `--force` kills by a pid Windows may have reused. → ownership by job `cwd`;
same-name live job from another cwd ⇒ rc 1 naming the owner; `.prev` keeps an epoch suffix.
**G7. Keep-awake keypresses cannot reach a LOCKED workstation** (synthetic input never reaches the
secure desktop) — the exact moment the machine is about to sleep. → every tick ALSO calls
`SetThreadExecutionState(ES_SYSTEM_REQUIRED)` one-shot (no `ES_CONTINUOUS`, nothing to leak; resets
the idle timer regardless of lock state). The F-key stays (owner asked for it) and only fires when
the user has been input-idle > 60 s and the station is unlocked — nobody typing ever catches a key.
**G8. The daemon must outlive its spawner.** `bg.sh`'s `( ) &` idiom survives a tool call, not a
closed terminal. → Windows spawn via `Start-Process -WindowStyle Hidden` (own console); any
session's next prompt re-ensures it anyway.
**G9. "Session is working" needs a real signal**, not just repo beats: a conductor's turn ends while
five background builders run; a non-POLARIS chat has no repo hooks. → machine-level hooks
(`UserPromptSubmit`=busy, `Stop`=idle, `SessionEnd`=gone) + per-session beats from the repo hooks
(subagent tool calls carry the parent's `session_id`) + live bg jobs. Hook stdout MUST be empty
(UserPromptSubmit stdout is injected into the model's context).
**G10. A capture nobody took.** v1 rejected any mechanical gate. v2 splits it: `handoff` proves a
capture EXISTS (visual-matched diff + `shot:` set ⇒ a fresh non-empty `.polaris/shots/<ID>-*.png`,
else rc 1 naming the command); prose proves someone LOOKED (`✅ saw:` line in the report, and the
Integrator opens the named PNG before landing). Neither replaces the other.
**G11. Two more human clicks are structural, not bugs**: the harness's self-modification classifier
prompts when the live `~/.claude/settings.json` is rewritten (dogfood/arm) and when a task edits the
repo's own `.claude/settings.json`. The plan pre-announces them; nothing else may prompt.
**G12. Windows `python3` is often the Store stub** — INIT/adopt derive `python`; the product repo's
`shot:` line is written with `python`, never `python3`.
**G13. The exact prompt spelling** the owner saw ("EnterWorkflow") is captured live during dogfood;
both `EnterWorktree` and `Workflow` are in the rule set (an unknown name is inert).

### WS1 — Worktree liveness: no session removes a worktree it cannot prove dead

Root cause and patch exactly as v1 (`wt_remove` primitive with rc 0 removed / 1 left / 2 archived;
`--force` leaves lib code; archive = `mv` to `.polaris/wt-archive/<ID>-<epoch>` + strip the `.git`

- **Beat file** `$GCD/worktrees/<ID>/polaris-beat` — writers: `beat_touch` from
  claim/resume/verify/handoff, the `ops/polaris` preamble when `$PWD` matches `*/.polaris/wt/<ID>`
  (`${PWD##*/}` gives the ID, zero-fork), and zero-fork `: >` touches in `checkout-guard.sh` +
  `ownership-guard.sh` (path = `${CWD%/.polaris/wt/*}/.git/worktrees/<ID>/polaris-beat`, string ops
  only; a missing dir is silently skipped). `readonly-allow.sh` stays write-free (its contract).
- **Lock meta grows lines 4–5**: `CLAUDE_CODE_SESSION_ID` and `CLAUDE_PID` — both are exported into
  every Bash-tool environment (probed today), stable for the whole session, unlike `$$`/`who()`.
  Existing 3-line parsers keep reading lines 1–3; a missing line reads `-`. Uses: `resume` allows a
  live lock when the lock's session id equals mine (a compacted session re-entering its own task),
  `sweep` prints "session alive" vs "session gone" (Windows: `ps -W` pid check, else `kill -0`),
  park stashes carry `<epoch>-<sid8>` so `unpark` can pop only OUR park (G5), bg jobs record the
  sid beside `cwd` for their refusal messages (cwd stays the ownership key — it also works in CI).
- **Liveness stays beat-only** (`beat_live` = age < `wt_live_minutes`, default 15, new KEYS row).
  The pid/sid lines inform messages and the same-session exception; they never decide removal.
- **`resume` is the lock-side twin** (`builder.sh:592` today adopts anything): live beat and a
  different session ⇒ die naming the beat file and the `rm <beat>` takeover; idle ⇒ adopt.
- **Lease steal becomes pid-aware** (`workspace.sh:111-113`): steal only if the holder pid is dead
  or absent, OR age > 2 × `integration_stale_minutes`; `land`/`seal` re-stamp the lease epoch
  between long steps so a slow suite never looks abandoned.
- **`sweep --fix` gains the worktree pass** (idle+clean ⇒ remove, + `branch -D` if task in `done/`;
  idle+dirty ⇒ archive; live ⇒ report with "last activity <n>m ago") — this is what makes the
  `finish` caveat and the `uninstall` die remedy true. Orphan-lock drop gains the 120 s grace.
- `done` runs `branch -D` only after `wt_remove` returned 0 or 2 (never on a LEFT worktree).
- Drill `wtreap` + `drill_selfland` assert as v1; `checkout-guard-denies` gains the worktree cases.

### WS3 — `polaris awake`: one keep-awake owner per machine

Replaces v1's WS3 wholesale. Probe-verified on this machine: Bash-tool/hook children live inside a
Windows Job Object (so `Start-Process` is NOT a safe detach); `CLAUDE_CODE_SESSION_ID` and
`CLAUDE_PID` are in the Bash env; `env -i` empties `$HOME` (hooks must carry absolute paths);
transcript `<sid>.jsonl` goes stale while a subagent runs but `<sid>/subagents/*.jsonl` is fresh;
PowerShell with the P/Invoke block costs 680 ms per tick; `OpenInputDesktop` returns 0 when locked.
- **Registry** `~/.claude/polaris/awake/` (root overridable by `POLARIS_AWAKE_HOME`):
  `sessions/<sid>` (4 lines: `busy|idle <epoch>` · transcript path · claude pid or `-` · repo
  primary or `-`), `repos/<cksum>` (line 1 primary path), `daemon/{pid,winpid,beat,log,hook.log,
  last-press}`, `lock/` (mkdir singleton), `stop`, `disabled`, `config`
  (`KEY=F15 TICK=55 STALE=2700 IDLE=900 GRACE=300 DISPLAY=1 INPUT_IDLE=60`, parsed by `case`,
  never sourced; `POLARIS_AWAKE_<KEY>` env wins — the drill seams). **No CONVENTIONS keys.**
- **Machine-level hooks** in `~/.claude/settings.json`, written by BOTH machine writers
  (`bootstrap.py::arm_machine`, `admin.sh::refresh_machine_kit`) through one merge implementation
  (`awake-hook.sh install`, identity regex `polaris/awake-hook\.sh`, foreign entries untouched,
  tmp+`os.replace`): `SessionStart`→`start` (create as idle only when absent — `compact`/`resume`
  must never downgrade busy), `UserPromptSubmit`→`busy` (+ ensure daemon), `Stop`→`idle`,
  `SessionEnd`→`end`. Every subcommand: `exec >/dev/null 2>>hook.log`, `trap 'exit 0' EXIT`,
  settings command ends in `2>/dev/null || true`; timeouts 5/10/5/5. **Zero stdout, always rc 0**
  (rc 2 on Stop means "keep going"; UserPromptSubmit stdout enters the model's context).
- **Activity beat = transcript mtime** (newest of `<sid>.jsonl` and `<sid>/subagents/*.jsonl`) —
  free, per tool call, every repo, every subagent. So NO per-tool machine hook and NO awake writes
  in the repo hooks. Verdict per tick: session `busy` and beat < STALE, or `idle` but beat newer
  than the idle stamp and < IDLE, or any registered repo with a bg job (no `rc`, pid alive) ⇒
  active ⇒ press. Sessions whose `CLAUDE_PID` is dead are dropped (hard kill, no SessionEnd); files
  older than 24 h are removed; a `busy` file costs at most STALE minutes, never forever. Quiet for
  GRACE ⇒ release lock, exit. `finish` never stops it; the next prompt anywhere re-spawns it.
- **Spawn (Windows)**: `Invoke-CimMethod Win32_Process Create` with the command line in an env var
  (child of WmiPrvSE — outside every caller job, no console, survives the spawning terminal);
  fallback `Start-Process -WindowStyle Hidden`; last resort inline `( ) &` + logged warning.
  macOS/Linux: `nohup … & disown` (macOS has no `setsid`). Two spawners racing: both `mkdir lock`,
  loser exits; steal only when `daemon/beat` > 3×TICK stale. `sleep TICK & wait $!` so `stop`
  interrupts within a second. Bash spawned via `bash.exe`'s absolute path (`find_bash`,
  `bootstrap.py:116-153`); powershell via `$SYSTEMROOT/System32/WindowsPowerShell/v1.0/`.
- **Press (Windows)** = one stateless `awake-press.ps1` per tick: P/Invoke `SetThreadExecutionState`,
  `GetLastInputInfo`, `OpenInputDesktop`, `keybd_event`. ALWAYS `ES_SYSTEM_REQUIRED` one-shot (the
  guarantee: resets the idle timer under Windows' 1-min floor, works on the lock screen, holds
  nothing). Unlocked + `DISPLAY=1` adds `ES_DISPLAY_REQUIRED` and the F-key (F13/F14/F15 by `KEY`,
  `none` disables) ONLY when input-idle > `INPUT_IDLE` s — a typing human never catches a key.
  Prints `pressed|skipped-active|skipped-locked|state-only` → `daemon/last-press`. Presser failure
  (GPO, Constrained Language Mode, AV) logs once per 100 ticks and never kills the daemon.
  macOS: `caffeinate -u -t 75` (`-i` when DISPLAY=0); Linux: `xdotool key F15` → `xdg-screensaver
  reset` → log once. Cannot cover lid-close/power-button/critical-battery — no user-mode API can.
- **CLI** `awake status|start|stop|disable|enable|install` in new `kit/ops/lib/awake.sh`
  (`cmd_awake`, `awake_ensure` fork-free when `daemon/beat` is fresh and a no-op when the machine
  is unarmed/CI, `awake_status_line`). `awake_ensure` fires from `claim`, `status`, `doctor`,
  `handoff`, `bg run`. `doctor` warns when unarmed or disabled. Loader list `+awake` after `bg`.
- **Drill `awake`** (policy.sh, template `drill_bg`), hermetic by construction: `spine.sh` exports
  `POLARIS_AWAKE_HOME=$T/awake-home` right after `T="$(mktemp -d)"` (so `bg run` inside ANY drill
  never registers a fixture repo on the owner's real registry); `bg-lifecycle.cmd` gets the same
  export. Seams: `PRESSER="touch $T/pressed"`, `TICK=1`, `IDLE=3`, `STALE=5`, `GRACE=2`,
  `SPAWN=inline`. Asserts: the 4 hook subcommands write the right files with empty stdout+stderr
  and rc 0 (JSON with a Windows-escaped `transcript_path`); `start` never downgrades busy; busy +
  fresh fake transcript ⇒ `pressed` within 3 s; all idle ⇒ no press, self-exit after GRACE, `lock/`
  gone; stale-daemon steal (`touch -t` backdate); `stop`; `disabled`; re-entrant start = one pid;
  bg-job clause; `install` merge on a fixture settings.json (foreign entry kept, stale ours
  replaced; skipped with a note when python is absent).
- **Golden deltas**: `api-kit` gains every `ah_*`/`awake_*` fn (exact names pinned in
  `keep-awake.md`; ≈19 in the hook, 5 in `awake.sh`, `drill_awake`, `merge_awake_hooks`) plus
  PROTOCOL's new `## AWAKE` H2; `cli-help` gains the 3-line `awake` usage block — but
  `cli-help.cmd` runs the INSTALLED `ops/polaris`, so that golden is re-pinned ONLY by the release
  task after dogfood (a wave-2 refresh would red the wave gate); `keys-drift` zero;
  `startup-budget` unchanged (the preamble beat is builtins-only; `awake_ensure` sits in the
  dispatch case, never on `_match|_rules|_guard`).
- Files: new `kit/ops/hooks/awake-hook.sh` (≤320 lines, bash 3.2 — CI runs macOS `/bin/bash`),
  new `kit/ops/hooks/awake-press.ps1` (≤80, not indexed), new `kit/ops/lib/awake.sh` (≤150),
  `kit/ops/polaris` (loader/dispatch/usage/ensure), `install.sh:106` chmod list, `bootstrap.py`
  (extract both files to `~/.claude/polaris/`, run `install`), `admin.sh` refresh (same, two-path
  fallback as :204-207), `observe.sh` doctor lines, `PROTOCOL.md`, `polaris-install/SKILL.md`
  "arms the machine" sentence, contract `ops/contracts/keep-awake.md`, module-layout v5 row.
