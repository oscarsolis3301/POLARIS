## Why
Owner decision R1: REA (the `rea-agents` npm package, github.com/morluto/rea) is standard equipment, so
"Use REA to…" works in any project on any machine POLARIS has armed. The installer already arms the
machine in `kit/ops/bootstrap.py` (`arm_machine`: the install skill, the cached kit, permissions,
keep-awake, model-guard); REA joins it there, inside the same `if permissions:` gate as model-guard.

Build exactly `ops/contracts/rea.md` § 1: a new `arm_rea()` plus constant `REA_FLOOR = "6.4.0"`.
`POLARIS_REA=off` skips everything silently. Already armed (`rea` resolves and
`~/.claude/skills/reverse-engineer-anything/` exists) runs nothing. Otherwise: Node ≥ 22.19 or one line
and carry on; `npm install -g rea-agents@6.4.0` if `rea` is missing (with a timeout), one line on failure;
then `rea setup --client claude_code --yes --json`, one line on failure. Lines go through `out()` only,
never `always=True` (ci.yml's quiet-install tripwire). Write the hermetic `rea-arm` golden with stub
binaries via `POLARIS_REA_PATH`, and set `POLARIS_REA=off` in the two in-repo fixtures that run the real
installer (`machine-armed.cmd`, `selftest-install.sh`) so no test can ever reach npm or the owner's
real REA registration. Re-pin `api-kit.expected` with exactly the two rows the contract pins.

- [ ] A quiet (non-verbose) install prints nothing new.
