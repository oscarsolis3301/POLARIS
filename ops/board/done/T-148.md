## Why
plans/v3.md § B4 says cross-device tracking is "mostly configuration": `claim: claim-branch` plus an
origin remote, because `sync_board()` opens with `has_remote || return 0` and without a remote every
board mutation is silently machine-local. Reading the code shows the other half is missing: with a
remote, every mutation PUSHES `refs/heads/polaris/board`, but nothing ever FETCHES it — a second
machine reads `ops/board/` exactly as it was at its last clone (`board_materialize` only fires when
the directory is absent). The claim-branch lock still prevents two machines building one task, but
`status`, `next`, `board-fm` and the dashboard on the second machine show a board that stopped
moving. `board_pull` is the read side: under `claim-branch` with a remote, fetch the ref (at most
once a minute), fast-forward the local ref when it is an ancestor of origin's, and re-materialize
the moved set with the same plumbing `board_materialize` uses — never a branch switch, never the
primary index. A diverged local ref is reported and left alone; a `local-lock` repo (this one) pays
nothing at all. Contract first-run.md § 5 pins the algorithm, the throttle, the four call sites and
the drill.

## Notes
- The moved set on the ref = `ops/board/**` + `ops/SPRINT.md` at their on-disk paths (MANUAL § Board commit by hand). Re-materializing over an existing dir must first REMOVE what the OLD tip tracked, or a task moved between folders shows up twice. Untracked local files under ops/board/ (a lock dir is elsewhere; IDEAS.md is tracked) are not yours to touch.
- Every existing drill runs under `local-lock`, so the gate makes them byte-identical; your new step is the only one that flips `claim:` — flip it back before the next step, and keep the scratch clone under `scratchpad/T-148/…`.
- `git fetch` in a drill against the bare origin is local and fast; never add a network fetch to any path a `local-lock` repo runs.
- Trust rc and file state, never a printed line (T-089); assert on files under active/ and the stamp, not on the `board pulled` wording alone.
- Bash ≥ 3.2: no `case` inside `$(...)`, no mapfile, no assoc arrays.
- assumed: the fast-forward writes only the paths that differ between the two tips (git diff --no-renames) rather than unlinking everything the local tip tracks + checkout-index -a — same result for committed state, and an in-flight task file's uncommitted Notes on this machine survive a pull (default-safe)
- assumed: both board_pull lines go to stderr — it is the first statement of board-fm (a parsed TSV) and next (line 1 is the verb), so stdout is not ours (default-safe)
- writes land before unlinks and update-ref goes last with compare-and-swap: a failure midway leaves a duplicate at worst, never a task missing from the next board commit (which rebuilds from disk)
- the throttle stamp carries the epoch of the last attempt and is read with a builtin — find -mmin rounds differently on GNU vs BSD and stat's flags differ, so "mtime" is realized as content
- checkout-index --stdin returns rc 1 for a path missing from the index even with -q, so the write set is --diff-filter=d (no deletions) and the unlink set --diff-filter=D
- the selftest's bare origin has HEAD → master: a second clone needs git clone -b main or it checks out nothing and claim_branch_take cannot resolve $BASE
- doctor --selftest --only remote,syncrace: 146 s green in the worktree; verify 11/11; fast tier 150 checks
