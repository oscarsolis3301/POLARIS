## Why
This is the fold card, the riskiest of the plan: guards fail open, so a dispatcher bug would switch
off every guard at once. `dispatch.sh <event>` reads the hook input once and, in order, runs the
model ban (every project, as the machine-level model guard does today), decides with builtins whether
it stands in a joined project (a vendored project's own hooks keep doing the work, so it stands
down there), then runs presence, the checkout deny and the read-only allow as functions in this one
process and prints the single verdict Claude Code would have reached from the four separate hooks
(hook-dispatch.md § 2). The edit guard, the hand-over hook and the permission hook are `exec`ed.

Two security pieces ride along. The read-only allow comes from a TRUST TIER copy that only the owner's
`--setup` writes (§ 4), so an automatic kit update can change what is denied but never widen what is
auto-approved. And in a joined project a command that runs `ops/polaris` is answered `ask` unless that
file is byte-for-byte the real launcher (§ 5), so a cloned repo cannot ride the pre-approved
`bash ops/polaris` rule. `shim.sh` is the small file `--setup` will copy to `$POLARIS_HOME/hook`.

The equivalence golden replays every existing guard battery through the dispatcher and must match
them exactly — it is on this card on purpose. Nothing registers the dispatcher yet (T-350, 7.0.0).

## Notes
- risk: high — the guard fold. Covered by the plan approval (approve --plan).
- Replay mechanism: a temp copy of each battery .cmd with its guard path rewritten (sed) — never edit the batteries themselves.
- exec with a here-string (`exec bash <file> <<<"$IN"`) passes the input with no fork.
- Tests never read the real ~/.claude: fake HOME and CLAUDE_CONFIG_DIR, POLARIS_PREFS= (empty = machine layer off), CLAUDECODE set or unset explicitly per case, PYTHONIOENCODING=utf-8 for any python that prints (Windows).
- Scratch paths per lane: scratchpad/T-345/… — never delete a shared scratch path.
- `bash kit/ops/polaris check --only …` is worktree-true; `find --api` is not (use `POLARIS_ROOT="$PWD" python ops/index.py find --api 'kit/*'`).
- Census goldens ride every card that edits kit/ops/polaris or kit/ops/lib/*.sh (api-kit, lib-census, keys-drift). A golden this card's change moves is this card's to re-pin; one it does not own → NEEDS PATH at once, never a workaround.
- Long command? `bash ops/polaris doc PROTOCOL "LONG COMMANDS"`. Never `doctor --selftest` in verify.
- project test order: CLAUDE_PROJECT_DIR walk first, then a .polaris/wt cwd, then the cwd walk only when the harness named no project — in a real session both name one repo; it keeps a golden run from a task worktree from reading as the vendored primary
- Stop/SubagentStop/StopFailure/Permission* exec with stdin untouched (no read, no here-string): permission-hook reads with read -d '' and a here-string's added newline would turn an empty payload non-empty
- model-guard's pending effort note (its only PreToolUse stdout) is folded into the verdict object as additionalContext — two JSON objects on stdout do not parse; an Edit with a note runs ownership-guard as a child and prints the note only on rc 0
- genuine launcher: after a not-genuine compare, ra_polaris_ok is redefined to return 1 and _ra_hook re-run — the allow is kept only if it did not need ops/polaris; also checked: the payload cwd's own ops/polaris; a NUL in either file = not equal
- SessionStart calls T-346's _ds_session <machine|vendored|auto> <root> <model-guard text> (auto when no project); verified against T-346's worktree file: one JSON object, rc 0
- fail open: trap 'exit "$DP_RC"' EXIT turns a crash (set -u in a guard, a broken trust copy) into rc 0 with no stdout; DP_RC is set only by a decided verdict
- known gap for the Planner: 'cd sub && bash ops/polaris …' runs sub/ops/polaris, which the genuine check does not follow (contract § 5 names the root only)
