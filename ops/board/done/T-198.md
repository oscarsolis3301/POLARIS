## Why
`finish` always runs `qa`, and qa runs the whole suite unless the last green run was at this exact
commit — so a docs-only commit (EVOLVE's, a sprint report) or a CSS tweak re-pays 26 minutes. This task
wires T-197's `depth_for` into the two callers (ops/contracts/test-depth.md § 4-5):

1. `cmd_qa` (observe.sh ~:2240-2306) and `land --express` (integrate.sh ~:659-711) ask depth_for.
   `none`/`look` run no suite key but every board check qa makes today; `scoped`/`full` unchanged.
   `qa --full`/`--force` and an unbounded change set stay full. Task files come from the `[<ID>]`
   subject scan (§ 4). `look` leaves the visual capture + `--saw` gate at handoff exactly as it is.
2. The stamp's third field records the depth word.
3. `surface_change_set` (core.sh ~:310) and `suite_stamp_carry` (integrate.sh ~:484) drop test_skip
   paths, so a green stamp carries across a docs-only commit.
4. Plan § E: every qa / land --express decision, and every `finish`, appends one row to
   `.polaris/decisions.ndjson` after the run (§ 5 shape). At most one new helper function for it.

CI and `pack.py --dogfood` still run the full serial suite and never read the stamp — untouched.
Drills that pin stamp format/behaviour (selftest history.sh ~:203-222, policy.sh ~:99-167, fast.sh
~:398-415) move only if their pinned meaning changed; say which in Notes. You own api-kit.expected
after T-197: add only your helper's line; STOP on any other hunk.

## Notes
- selftest verdict: `bash kit/ops/polaris doctor --selftest --only qa,express,surfaces,finish` → SELFTEST-PASS, rc 0 (run via `bg run` + chunked `bg wait`, ~6m).
- history.sh/policy.sh: no drill MOVED — pinned meaning unchanged in both (history.sh ~203-222 express-carry stamp shape, policy.sh ~99-167 surfaces scoped/full selection). Their probe files DID change: `*.txt` is in the kit's own default `test_skip` glob (KEYS.tsv, T-197), and `surface_change_set`/`depth_for` now read it — so the drills' own `.txt` stand-ins for source code (src/sf/a.txt, tests/sf/a_test.txt, src/tpl/x.txt, src/ex.txt in history.sh's express drill) were silently swept out of the change set, going `none` instead of their intended scoped/full/red verdict. Renamed those probe files to `.dat` (same convention test-depth.cmd already uses for this exact reason); the shared `src/a.txt` used by unrelated drills elsewhere is untouched, and `drill_surfaces`'s "unmapped change" probe now writes a new dedicated `src/surfaces-unmapped.dat` instead of touching that shared file.
- cmd_qa's depth gate only consults depth_for when the tree is clean (added `[ -z "$dirty" ]`): depth_for sees committed diffs only, so on a dirty tree (e.g. an uncommitted CONVENTIONS.md edit adding a new suite key) a bounded-but-empty committed diff would read as `none` and skip the suite entirely — caught by history.sh's "QA STAMP FORMAT FAIL" drill, which this guard fixes without touching the drill.
- land --express's own gate has no such guard: by the time step 3 runs, `cmd_land` has already squashed a commit, so the diff is never empty there.
- decision_log is the one new helper (core.sh, § E's cap); it's called from cmd_qa, cmd_land_express and cmd_finish.
