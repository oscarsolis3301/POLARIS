## Why
Every "two chats, one repo" failure this plan fixes bottoms out in mechanics no module owns today:
branch IDs are never validated so a stray ref literally named `feat` poisons `worktree add` with the
real error swallowed; six commands die on a dirty tree without naming whose dirt it is; the
integrator path has no concept of "another session holds the lane". This task builds the module that
owns those mechanics — `kit/ops/lib/workspace.sh` — exactly as `ops/contracts/shared-checkout.md`
specifies: `id_ok`, `wt_add` (captured stderr, retry ONLY on real index.lock contention),
`stray_feat_repair` (rename to `stray/feat-<sha7>`, local + origin — archive, never delete),
`int_on`/`int_off` (the integration lease: poll 2s with progress notes, steal only past
`integration_stale_minutes`, rc 3 with one `queued: ` line past `integration_wait_minutes` — never
a question), `wave_on` (create / ff-reuse / ADOPT integrate/<date>), `park`/`unpark` (named stash
`polaris/park-<epoch>`, `--include-untracked`, reversible in one command).

The CLI surface rides along: the loader's FULL-load list gains `workspace` between `ownership` and
`builder` (the `_match|_rules|_guard` short path stays EXACTLY `core ownership` — the write-guard's
latency budget must not pay for this module), dispatch + usage() gain `park`/`unpark`, and core.sh's
`on_die` gains `${INT_HELD:-}`-guarded lease cleanup so a crashed holder never costs 45 minutes.

This task adds this sprint's only non-drill top-level fns, so it also owns the golden that records
the kit surface: hand-author the `ops/tests/api-kit.expected` delta for workspace.sh's fns.

## Acceptance criteria (binary — each becomes a test; put the runnable ones in verify:)
- [ ] `workspace.sh` defines exactly the contract's fns, ≤350 lines, definitions only (no top-level
      executable code — module-layout invariant)
- [ ] `id_ok` rejects an empty ID, a bare `feat`, and anything `git check-ref-format` refuses, with
      one ⛔ line; accepts every ID the board has ever used (T-0.., letters/digits/dashes)
- [ ] `wt_add` never writes `2>/dev/null` on the worktree call: stderr is captured; retry fires only
      when it mentions index.lock; other failures re-emit it verbatim and die
- [ ] `stray_feat_repair` renames a local branch named `feat` to `stray/feat-<sha7>` and repairs an
      origin `feat` the same way (push new name, delete old); no such ref → silent rc 0
- [ ] `int_on` on a free lane takes it instantly; on a busy lane polls 2s with a progress note about
      every 30s; on a lease older than `integration_stale_minutes` (default 45) steals with a note;
      past `integration_wait_minutes` (default 10) prints ONE line beginning `queued: ` and exits 3
- [ ] `int_on` is re-entrant (already ours → rc 0); `int_off` releases only our own lease
- [ ] `on_die` releases the lease when `INT_HELD` is set; the `_match`/`_rules` guard path is
      untouched (short list unchanged, no workspace reference reachable from it)
- [ ] `wave_on` does create / ff-reuse / adopt and SAYS which; the caller-holds-lease precondition
      is documented in its header comment
- [ ] `park` stashes tracked + untracked under `polaris/park-<epoch>` and prints a line containing
      `parked as polaris/park-`; stash failure → rc 1 with the tree untouched; `unpark` restores the
      newest park byte-identically; nothing to park/unpark → friendly note, rc 0
- [ ] `polaris park` / `polaris unpark` dispatch in `kit/ops/polaris`, documented in usage(), and
      the help fast path stays ABOVE the module loader (startup-budget golden shape)
- [ ] `ops/tests/api-kit.expected` gains exactly workspace.sh's fn lines (hand-authored, byte-exact
      per the Notes recipe) — no other golden touched

- Golden recipe (T-047, proven): `check`/`find` are PRIMARY-anchored, so you cannot prove the golden
  from your worktree with the installed CLI. Replicate the generator instead: run `python ops/index.py`
  with POLARIS_ROOT pointed at your worktree, emit the `--api 'kit/*'` shape, and hand-author the
  byte-exact delta into `ops/tests/api-kit.expected` on your branch. The wave gate (uat on the
  integrate checkout) is what proves it end-to-end.
- The board mutex pattern to mirror for the lease is `mutex_on` (kit/ops/lib/core.sh:175) — epoch
  file, stale steal, bounded loop. Different lock dir (`$LOCKS/.int-lease`), different bounds (cfg
  knobs), different timeout behavior (rc 3 + `queued: `, never die).
- Lock ordering (contract): the lease is OUTERMOST — never `int_on` while holding the board mutex.
- The installed `ops/polaris` lags your kit edits all sprint: prove behavior with
  `bash kit/ops/polaris …`, board mechanics with the installed CLI.
- bash 3.2: no `case` inside `$(...)`; split `local` declarations (one per line when one references
  another).
- Never run `doctor --selftest` while your kit edits are half-written — a mid-edit suite fabricates
  a different spurious failure each run.
- Long suites FOREGROUND with an explicit ≥600000ms tool timeout (test_fast ≈320s); past the cap →
  log to a file and poll for `selftest passed`. Never end a turn waiting on a notification.
- int_on inside `$( )` self-releases at the substitution's end (its EXIT trap fires in that subshell) — consumers call it at statement level, never capture its output.
- park/unpark byte-identical restore holds under core.autocrlf=false (drill repos should set it); autocrlf=true machines see git's own CRLF normalization on pop, not a park defect.
