## Why
Contract safe-landing sections 6-7, on top of T-224's helper and re-land. cmd_seal runs landed_content_ok over each task whose [<ID>] commit it just merged; a mismatch prints the warning line '⚠ <ID> did not fully arrive — re-landing' and re-lands that task in the same lease, then carries on (all green prints nothing new). cmd_finish gains one gate: every task in done/ this run (plan: matches the run's plan record, or all of done/ when there is none) must pass landed_content_ok (rc 0 or 2); otherwise ONE line '⛔ <ID> is done but its files are not on main: <paths>' and a non-zero exit. Healthy runs print nothing new. Golden landed-seal covers: a sealed wave with a clobbered path is re-landed and says so; a healthy seal output is unchanged; finish refuses a done task whose file is missing (build the fixture so the branch still exists).
