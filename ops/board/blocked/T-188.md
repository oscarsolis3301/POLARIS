## Why
Owner decision R1 says REA stays updated on every armed machine with nobody doing anything. A bad REA
release published today must not reach every machine today, so an update waits until the newest release
has been out for at least 7 days.

`polaris update` itself lives in `kit/ops/lib/admin.sh` (`cmd_update` / `cmd_update_auto`), but that
code almost never runs: `kit/ops/hooks/update-hook.sh` returns before starting the CLI on nearly every
session (its no-CLI fast path), and it exits early in the kit's own repo. So the daily trigger goes in the
hook, and the work goes in a new flat script, exactly as `ops/contracts/rea.md` § 2 pins:
`kit/ops/hooks/rea-update.sh` (no functions; stamp first; `npm view`; compare with `rea --version`; wait
while the latest release is younger than 7 days; else `rea update` then `rea setup --client claude_code
--yes --json`; fail open everywhere) and, inline in `uh_main` before the self-hosting exit, a builtin check
of the machine stamp that starts the job through `bg run rea-update` when it is not today's. `--test`
prints `update-hook: would start rea-update` instead of launching.
