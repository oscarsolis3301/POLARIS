## Why
A self-landing lane leaves its own `feat/<ID>` behind on purpose (worktree-liveness v1.2: never
remove the ground you are standing on). `drift` then calls it CRUFT, `qa` runs `drift --strict`
AFTER the suite, goes red, writes no suite stamp — and the `finish` that follows re-runs the whole
~12-minute suite for a nit `sweep --fix` clears in a second. Observed twice on 2026-09-14; both runs
paid the suite twice for exactly this. It is structural, so the fix lives in the commands: a branch
is cruft only with PROOF that its tip landed (the squash commit's `Landed-from:` trailer, or base
ancestry); a proven branch whose worktree is still live is a lane stepping out, not cruft, and drift
says nothing; a proven idle one is cleared by `qa` before drift ever looks; an unproven one is
reported as diverged and never auto-deleted. `sweep` reuses the same function so there is one
implementation of "safe to delete".

## Notes
- The waiting class needs a registered worktree with a FRESH beat in the fixture: `git worktree add .polaris/wt/<ID> feat/<ID>` then touch `$(git rev-parse --git-common-dir)/worktrees/<ID>/polaris-beat` — `beat_live` reads that file (workspace.sh); `wt_live_minutes` defaults to 15.
- `landed_sha` (integrate.sh) finds the `[<ID>]` commit on base; the trailer is `Landed-from: <sha>` in its body — `git log -1 --format=%B <landed> | sed -n 's/^Landed-from: *//p'` is what `sweep`'s remote pass already does; reuse the shape.
- `qa` is run by `finish` and by CI; deleting a proven branch is the ONLY new mutation. Do not clear anything without the proof, and do not touch `drift`'s read-only nature.
- The handover-route golden runs `drift` after a promote on a fixture with no feat branches — byte-identical by construction; `bash ops/tests/handover-route.cmd | diff - ops/tests/handover-route.expected` (47 s, run once as an acceptance check) proves it.
- Per-lane scratch (`mktemp -d`), never a shared path; trust rc + refs over printed text (T-089).
